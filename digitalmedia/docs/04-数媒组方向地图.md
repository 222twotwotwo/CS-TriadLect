# 04 · 数媒组方向地图

这篇回答一个问题：**"数媒组到底做什么？"**

它不打算把你教成谁 —— 它是一张地图：**有哪些方向、各自在干什么、和这个项目哪一块对得上、
想入门先学什么。**

> ⚠️ **这份文档是半成品，而且是有意如此。**
> 下面每个方向的"它在干什么""入门先学什么"，我按行业里的通行理解写了；
> 但**具体到我们组在做什么项目、用什么工具链、招人时看什么** ——
> 那些地方我标了【待补充】。那些内容得由组里的人来写，不能靠推测。

## 一张总表

组里招新页上的标签是 **DCC / Game Engine / AIGC / XR**。展开成方向：

| 方向 | 一句话 | 本项目里对应哪一块 |
|---|---|---|
| 游戏引擎 / 图形开发 | 把画面算出来的人 | **整个项目都是** —— 光栅化、光照、多线程 |
| 引擎 / 运行时 | 让引擎跑得快、跑得稳的人 | `core/raster.cpp` 的 tile 分桶与多线程、`core/framebuffer.h` 的推屏优化 |
| **技术美术（TA）** | 站在美术和程序中间，把"好看"翻译成"参数" | **第 2 关**（PBR 材质）、**第 3 关**（纹理采样） |
| DCC → 引擎链路 | 把 DCC 里做的东西正确地送进引擎 | 第 3 关的 UV / 寻址 / 滤波 —— 这正是资产导入最常出问题的地方 |
| 数字孪生及其可视化 | 把真实空间搬进屏幕里 | 场景主题本身就是"数媒组工作室的数字孪生" |
| 三维仿真开发 | 仿真 + 交互，不只是"看" | 【待补充】组里在这块的落地 |
| 数字人开发 | 会说话、有表情、能动的人 | 【待补充】 |
| 影视与虚拟制片 | 实时画面 + 摄影机语言 | 【待补充】 |
| XR 应用 / 开发 | 把画面塞进头显 | 【待补充】 |

## 四个关卡 = 四个方向的切片

这不是巧合 —— 关卡的顺序是照着**一条真实的渲染学习路径**排的：

| 关 | 你要做的事 | 它对应的工作 |
|---|---|---|
| 0 · 黑暗 | 改环境光系数，让房间亮起来 | **图形开发**：光照模型是什么、着色器是什么 |
| 1 · 第一束光 | 把灯装回吊灯、拧对强度 | **引擎 / 灯光**：点光源、平方反比衰减、为什么"位置比强度重要" |
| 2 · 材质 | 照着样板改三个球的 albedo/roughness/metallic | **技术美术**：PBR 参数到底在调什么 |
| 3 · 纹理 | 把地板铺成方格砖 | **技术美术 / DCC 链路**：UV、寻址模式、滤波 —— 资产从 DCC 到引擎最常翻车的地方 |

**技术美术（TA）** 值得单独说一句，因为它是这个项目里出现最多的方向，也是最难自学的方向：
它要求你**同时听得懂两边的话** —— 美术说"这个球看着假"，你得知道那是 roughness 的问题；
程序说"这个 draw call 太贵"，你得知道那等效于美术上的什么取舍。

第 2 关设计成"照着旁边的样板球调参数"，就是这个岗位日常的缩影：
**别人给你一个目标结果，你要找到那组参数。**

## 想入门，先动哪个？

按门槛从低到高：

| 你的情况 | 从哪开始 |
|---|---|
| 完全没写过代码 | 第 3 关 —— 改 `content/textures.txt` 三个词，按 R 看地板变化。零代码，全是"调参数看结果" |
| 有点编程基础 | 第 0 关 —— 改一个着色器常数、重新编译。第一次体会"我改的代码变成了屏幕上的光" |
| 想往图形/引擎走 | 读 `core/raster.cpp`。那是这个项目最硬核的 300 行 |
| 想往技术美术走 | 第 2 关 + `game/shaders/lighting.cpp` 里的 GGX 高光那几行 |

**看完这篇，建议回去把四关打一遍。** 地图看再多遍，不如自己把一间黑屋子点亮一次 ——
那时候你就知道"渲染"这个词具体指的是什么了。
