# 02 · 报错急救表

**按症状查。** 这份文档存在的理由很具体：第一次跑这个项目的人，遇到的十有八九是下面这些，
而它们大多**不是坏了**，是设计如此。

先记住一句：**这个项目不会悄悄出错。** 数据文件写坏了它会出声拒绝，
字模找不到了它会画红块，参数写错了它直接报错退出 —— 宁可吵你一下，也不给你一个看起来正常、
其实不对的画面。

---

## 一、编译 / 启动

| 症状 | 原因 | 怎么办 |
|---|---|---|
| `[build] no C++ compiler found.` | 没装编译器，或 `vswhere` 探测不到 | 装 Visual Studio 2022（勾「使用 C++ 的桌面开发」），或 MinGW g++。见 [01-环境搭建](01-环境搭建.md) |
| 编译报一堆 `error C2xxx` | 你的编译器太老，或者用的是别的标准 | 需要 **C++17**。VS 2019 及以上 / g++ 9 及以上 |
| 双击 `dreamlab.exe` 闪一下窗口就没了 | 缺文件时的正常报错行为 | 用 cmd 跑 `build\dreamlab.exe`，或双击 `run.bat`，这样能看到输出 |
| 控制台中文是乱码 | cmd 默认码页（中文 Windows 上是 936） | **双击 `run.bat`** —— 它先 `chcp 65001`。或者自己先敲一次 `chcp 65001` |
| `[错误] 未知参数: xxx（用 --help 查看用法）` | 参数名写错了 | `build\dreamlab.exe --help` 看完整参数表 |

## 二、画面

| 症状 | 原因 | 怎么办 |
|---|---|---|
| **满屏红色色块**（整个界面都是红块） | **字模整份没加载成功** | 确认 `assets/font/pixel12.bin` 在（约 165 KB）。丢了就 `python tools/gen_font_atlas.py` 重新烘焙（需要 Pillow）。也可能是你没在仓库根目录下运行 —— 程序会自动往上找仓库根并打印 `[路径] 当前目录不是仓库根，已切到 …` |
| **个别字是空心方框**，同时 stderr 有 `[font] 字集里没有 U+xxxx` | 那个字不在字模里 | 字模覆盖 17,573 个常用汉字，极生僻的字没有。要加：改 `tools/gen_font_atlas.py` 的 `EXTRA_SYMBOLS` 后重跑脚本 |
| 画面全黑，什么也看不见 | **这是第 0 关本身** | 不是 bug。你身上有一点微光，远处终端屏幕亮着 —— 跟着它走 |
| 画面糊 | `--scale` 调过 | `--scale 1`（默认）是原分辨率。`--scale 2` 会按一半分辨率渲染再放大，中文会糊 |

> **红块和空心框是两回事，一眼就能分：** 红块 = 字模**整份**没加载（看文件在不在）；
> 空心框 = **某一个字**不在字模里（不影响其它字）。

## 三、改了 `content/` 没反应

这是最常见的一类。**先看游戏内控制台说了什么** —— 走到桌子前的终端按 `E` 打开，敲 `reload`。

| 控制台说 | 意思 | 怎么办 |
|---|---|---|
| `content/ 没有变化（和上次读进来的一模一样）` | 文件内容和上次读进来的一样 | 确认你**存盘了**（编辑器没保存的话文件没变） |
| `重新应用了 N 个文件` | 成功 | —— |
| `重新读了 N 个文件；报错的那几个整份没生效，其它照常` | **有文件写坏了** | 看上面的具体报错行 |
| `content/xxx.txt:12: 未知字段 "roudhness"（是不是想写 roughness？）` | 字段名拼错了 | 照建议改。注意报错会给**文件名 + 行号 + 拼写建议** |
| `content/xxx.txt:38: wrap 只认 repeat… 或 clamp…；"repeta" 不认识（是不是想写 repeat？）` | 那个字段的值是**词**不是数字 | 照建议改 |
| `"xxx" 是关卡的标准答案，上着锁 —— content/ 改不动它。` | 你改的是**样板材质**（答案本身） | 第 2 关要改的是展台上那三个球（`chrome` / `plastic` / `clay`），不是 `ref_*` 那几个样板 |
| `content/xxx.txt: 打不开这个文件（要在仓库根目录下运行程序）` | 工作目录不对 | 从仓库根目录运行程序（双击 `run.bat` 也行，它会切过去） |

**关键理解：数据文件坏掉时，程序会退回代码里的默认值 —— 世界看起来"正常"，但那是出厂状态。**
所以"改了没反应"的正确查法永远是先看控制台有没有报错，而不是盯着画面猜。

## 四、关卡进度不动

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 改了数据、按了 R，进度条不动 | 改的可能不是这一关要的那个数 | 敲 `level` 看这一关的目标；敲 `inspect <材质名>` 看当前实际数值 |
| 进度卡在 40% / 70% 这种整数 | 那一关是多件事加权计分的 | 第 3 关是 平铺 40% + 寻址 30% + 滤波 30%，三件全对才 100% |
| 我明明改对了却不过关 | 检查是不是改到了**另一个材质** | 第 2 关每个球比的是**它自己的样板**（`chrome` 比 `ref_chrome`），三个球抄成同一个值只值 33% |
| 想确认判定到底读到了什么 | —— | 开窗时进度条下方会同步显示；离屏跑 `--level N` 会打印一行 `[关卡] … 进度 x%` |

## 五、想推倒重来

| 想干什么 | 命令 |
|---|---|
| 存档坏了 / 站在了墙里 / 想回出生点 | `build\dreamlab.exe --reset`（会删掉 `saved/save.bin`） |
| `content/` 改乱了想恢复 | 见下面「改崩了怎么恢复」 |
| 一切从头 | 删掉 `build/`、`build-cmake/`、`saved/` 重新构建 |

### 改崩了怎么恢复

`content/*.txt` 是这个项目里你**唯一**会大量手改的东西，也是最容易改崩的。三个办法，从轻到重：

1. **看报错的行号。** 解析器会告诉你是哪个文件、第几行、以及拼写建议 —— 大多数情况看一眼就修好了。
2. **整份还原。** 数据文件坏掉时程序会用代码默认值跑，所以画面不会崩；改回来按 `R` 就恢复了。
3. **从 git 还原**（如果这是 clone 下来的）：
   ```bash
   git checkout -- content/
   ```

> 建议：**动手改 `content/` 之前先备份一份**，或者干脆养成"改一次存一次盘、按一次 R"的习惯 ——
> 有反馈就不会一次改崩十个地方。

## 六、性能 / 其它

| 症状 | 怎么办 |
|---|---|
| 帧率低 | 这是个纯 CPU 的软光栅化器。换小一点的窗口（`--width 960 --height 540`），或 `--fpscap 30` 锁帧省电。**机器上有别的重负载时帧率会掉到大约一半** —— 那是正常的 |
| 窗口太大 / 太小 | 按 `Esc` 开暂停菜单改分辨率与窗口模式（上限 720p）。也可以用 `--width` / `--height` 指定 |
| **进了全屏出不来 / 想改回窗口** | 按 `Esc` 开菜单 → 窗口模式 → 窗口。**全屏不吞 Esc**，这是设计保证的 —— 菜单里永远有"窗口模式"和"退出游戏"两条退路 |
| 想退出游戏却退不掉 | 按 `Esc` → 菜单 → 退出游戏。**Esc 本身不再直接退出**（以前手滑按两下游戏就没了） |
| 窗口设置被改乱了 | 删掉 `saved/settings.txt`，下次启动回默认。注意它是**独立于存档**的：`--reset` 只清进度，不会动它 |
| `[错误] --cam 需要三个数，用逗号隔开` | `--cam` 和 `--look` 是**逗号**分隔：`--cam 0,3,4`。写成空格会报错退出（以前会安静忽略，浪费过一轮排查） |
| 屏幕上没有准星 | 离屏 `--shot` 不画准星 —— 出的图是当素材用的，不该烧一个十字上去 |
| 想知道一帧到底干了多久 | `--trace`：`work=` 是一帧真正干活的时间，`period=` 是帧间隔（含限帧等待） |

---

**没找到你的症状？** 那就把完整的输出（从命令行到报错）看一遍 —— 这个项目的报错都很具体，
基本都会告诉你哪个文件、第几行、该怎么改。
